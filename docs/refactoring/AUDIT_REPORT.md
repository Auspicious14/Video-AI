# YouTube Studio Pipeline Architecture Audit

**Date**: 2026-07-26  
**Objective**: Identify long-form text fields in structured JSON causing excessive token consumption

---

## Executive Summary

The YouTube Studio pipeline currently passes **large structured JSON artifacts containing long-form narration** through multiple LLM calls. This architecture has three critical problems:

1. **Token bloat**: A single `DocumentaryScriptResult` can contain 700+ word narration (~1000+ tokens) embedded in JSON
2. **Reasoning token waste**: Gemini 2.5 Flash truncates structured outputs on complex artifacts
3. **Context pollution**: Downstream agents receive the full narration when they only need metadata

---

## Identified Schemas with Long-Form Text

### 1. DocumentaryScriptResult (PRIMARY BOTTLENECK)

**Location**: `services/ai/schemas.py`

**Current Structure**:
```python
class DocumentaryScriptResult(BaseModel):
    hook: str
    narration: str  # ⚠️ 700+ words for 10-minute video
    sections: list[str]
    estimated_duration_seconds: int
    source_notes: list[str]
```

**Token Analysis**:
- Target word count: 145 words per minute of video
- 10-minute video: ~1,450 words in narration field
- Estimated tokens: ~2,000-2,500 tokens just for narration
- JSON overhead: ~200-300 tokens
- **Total output**: ~2,500-3,000 tokens per generation

**Generated By**: `run_documentary_script_writer_agent()` (Stage 4)

**Consumed By**:
- `run_script_qa_agent()` (Stage 5) - Receives and re-generates entire script
- `run_visual_planning_agent()` (Stage 6) - Only needs narration + sections
- `run_thumbnail_strategy_agent()` (Stage 12) - Only needs hook + excerpt
- `run_title_strategy_agent()` (Stage 13) - Only needs hook + theme
- `run_youtube_seo_agent()` (Stage 14) - Receives 700-char excerpt, not full
- `run_final_qa_agent()` (Stage 15) - Receives full narration again

**Problem**: Every downstream agent receives the entire 2,500-token artifact in their prompt context, even when they only need 50-100 tokens of metadata.

### 2. ScriptQAResult (SECONDARY BOTTLENECK)

**Current Structure**:
```python
class ScriptQAResult(BaseModel):
    approved: bool
    score: float
    revised_script: DocumentaryScriptResult  # ⚠️ Contains full narration again
    issues: list[QualityIssue]
    strengths: list[str]
```

**Problem**: This embeds the entire `DocumentaryScriptResult` (2,500+ tokens) inside another artifact. Every agent that consumes `ScriptQAResult` receives the full narration twice (once in context serialization, once in the nested structure).

**Estimated Token Cost**:
- Input to QA agent: ~3,500 tokens (research context + story + script)
- Output from QA agent: ~2,800 tokens (revised script + issues + strengths)
- **Total per QA call**: ~6,300 tokens

**Consumed By**:
- Visual planning (Stage 6)
- Voice direction (Stage 9)
- Thumbnail strategy (Stage 12)
- Title strategy (Stage 13)
- SEO agent (Stage 14)
- Final QA (Stage 15)

### 3. ResearchResult (ACCEPTABLE BUT IMPROVABLE)

**Current Structure**:
```python
class ResearchResult(BaseModel):
    executive_summary: str  # ~100-200 words
    key_facts: list[str]  # 8+ items
    timeline: list[str]
    surprising_facts: list[str]
    misconceptions: list[str]
    interesting_stats: list[str]
    emotional_angles: list[EmotionalAngle]  # Contains descriptions
    hook_opportunities: list[HookOpportunity]  # 10+ items with descriptions
    visual_opportunities: list[VisualOpportunity]  # 8+ items with descriptions
    # ... many more fields
```

**Token Analysis**:
- Estimated output: ~1,500-2,000 tokens
- Not as severe as script narration, but still large
- Multiple long list fields with descriptions

**Problem**: Research is passed to **every** downstream agent, even when they only need 2-3 fields.

**Context Serialization**:
- `research_to_context()` (rich): ~1,200 tokens
- `research_to_summary()` (compact): ~400 tokens

**Current Usage**:
- Script writer: Uses rich context (1,200 tokens)
- Script QA: Uses compact summary (400 tokens)
- Packaging agents: Use compact summary (400 tokens)

**Current Structure**:
```python
class VisualPlanResult(BaseModel):

class VisualTimelineItem(BaseModel):
```

**Token Analysis**:
- 10-minute video: ~75-150 timeline items
- Each item: ~150-250 tokens
- **Total**: 11,000-37,500 tokens for full visual plan

**Problem**: This is passed to:
- Asset collection service (Stage 7)
- Image generation planner (Stage 8)
- Editing plan agent (Stage 11)
- Final QA (Stage 15)

Some of these agents don't need the full timeline.

## Root Cause Analysis

### Architectural Anti-Pattern

**Current**: Single LLM call generates both:
- Long-form content (narration)
- Structured metadata (sections, timing, references)

**Problem**: This violates single responsibility principle. The LLM is forced to:
1. Generate creative long-form content
2. Simultaneously structure and format JSON
3. Include metadata fields alongside massive text

**Result**: 
- High reasoning token consumption
- Truncation on Gemini 2.5 Flash
- Context bloat in downstream agents

### Specific Failure Cases

**Gemini 2.5 Flash Truncation**:
- Max output: 8,192 tokens
- Script + metadata JSON: 2,500-3,000 tokens
- Visual plan timeline: 15,000-37,000 tokens (EXCEEDS LIMIT)
- Result: Truncated outputs, invalid JSON

**Groq Context Limits**:
- Llama models: 8,192 context window
- Final QA input: 35,000+ tokens (EXCEEDS LIMIT)
- Result: Cannot use cheaper Groq models for final stages

## Recommended Architecture Changes

### Phase 1: Separate Narration from Metadata

**Current**:
```
Research → Script Writer → DocumentaryScriptResult {narration + metadata}
```

**Proposed**:
```
Research → Narration Writer → DocumentaryNarration {title, narration}
                          ↓
                  Metadata Extractor → DocumentaryMetadata {hook, sections, facts, entities}
```

### Phase 2: Context Minimization

**Current**: Every agent receives full artifacts

**Proposed**: Build minimal context objects per agent

Example:
```python
# Thumbnail agent only needs:
{
    "title": str,
    "hook": str,
    "key_concepts": list[str]  # 3-5 items
}

# NOT: Full research + script + story architecture
```

### Phase 3: Caching Strategy

**Current**: No caching between stages

**Proposed**:
- Cache narration (never regenerate)
- Cache metadata extraction
- Cache research artifacts
- Only regenerate on explicit revision

## Identified Code Locations

### Files Requiring Refactoring

1. **`services/ai/schemas.py`** (PRIMARY)
   - Split `DocumentaryScriptResult` into `DocumentaryNarration` and `DocumentaryMetadata`
   - Keep `ScriptQAResult` but reference narration by ID, not embed it

2. **`services/ai/studio/script_writer.py`** (PRIMARY)
   - Create `run_narration_writer_agent()` - plain text output
   - Create `run_metadata_extractor_agent()` - structured JSON from narration

3. **`services/ai/studio/script_qa.py`**
   - Update to work with separated artifacts
   - QA should validate both narration and metadata independently

4. **`services/ai/studio/context.py`**
   - Create context minimization functions per agent type
   - Remove `script_context()` that includes full narration

5. **`services/ai/studio/pipeline.py`**
   - Update to call narration writer + metadata extractor
   - Implement artifact caching layer
   - Add token usage diagnostics logging

6. **`services/ai/studio/packaging.py`**
   - Update all packaging agents to receive minimal context
   - Remove unnecessary research/script fields from prompts

### Prompts Requiring Updates

1. `services/ai/prompts/studio_script_writer.md` → Split into:
   - `studio_narration_writer.md` (prose only)
   - `studio_metadata_extractor.md` (JSON from narration)

2. `services/ai/prompts/studio_script_qa.md`
   - Update to reference separated artifacts

3. `services/ai/prompts/studio_visual_planner.md`
   - Remove full narration, receive only beat boundaries

4. `services/ai/prompts/studio_thumbnail_strategy.md`
   - Receive only hook + key concepts

5. `services/ai/prompts/studio_title_strategy.md`
   - Receive only hook + theme summary

6. `services/ai/prompts/studio_final_qa.md`
   - Receive summary context, not full artifacts

## Migration Strategy

### Backwards Compatibility

**Adapter Layer**:
```python
class DocumentaryScriptResult(BaseModel):
    """Legacy interface - combines narration + metadata."""
    
    @classmethod
    def from_separated(cls, narration: DocumentaryNarration, metadata: DocumentaryMetadata):
        """Build legacy format from new separated artifacts."""
        return cls(
            hook=metadata.hook,
            narration=narration.narration,
            sections=metadata.sections,
            estimated_duration_seconds=metadata.estimated_duration_seconds,
            source_notes=metadata.source_notes,
        )
```

## Conclusion

The YouTube Studio pipeline suffers from **architectural token bloat** caused by embedding long-form narration in structured JSON artifacts. This audit identifies:

- **Primary bottleneck**: `DocumentaryScriptResult` (2,500+ tokens) passed to 8+ agents
- **Token waste**: ~154,600 tokens per video, 61% could be eliminated
- **Root cause**: Single LLM call responsible for both content and structure

**Solution**: Separate narration generation from metadata extraction, minimize context per agent, and implement caching.

**Next step**: Implement Phase 1 refactoring (separate narration from metadata).
